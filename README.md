# Луза — бильярдный клуб

Рабочий гостевой MVP бильярда для браузера с интеграцией Telegram Mini App SDK (на реальных клиентах Telegram пока не проверен): React + TypeScript, настоящий 3D-стол на Three.js, общая физика и авторитетный WebSocket-сервер.

## Запуск

Требуется Node.js 22+.

```sh
npm ci
npm run dev
```

Интерфейс: `http://localhost:5173`. Vite проксирует `/ws` и `/api` на сервер `3001`. Оба сервера слушают `0.0.0.0`; браузер использует только адрес текущего сайта. Разрешён preview-домен `*.e2b.app`.

```sh
npm test       # 19 тестов физики, правил, интерполяции и онлайн-комнат
npm run build  # TypeScript + production-сборка
npm start      # один Node-сервер: сайт, /ws и /api/health; порт 3001
# PORT=8080 npm start
```

Установка production должна включать devDependencies: сервер запускается через `tsx`. `dist/` генерируется сборкой и не хранится в Git.

### Проверка игры вдвоём

1. Открой сайт в двух вкладках / браузерах / на двух устройствах.
2. В каждом окне нажми **Найти соперника** (на телефоне — **Играть онлайн**). В очереди только настоящие подключённые игроки, без искусственного счётчика и ботов.
3. Альтернатива: **Пригласить друга → Создать свой стол**. Скопируй ссылку нажатием на код комнаты или введи код на другом устройстве.
4. Удар делается кием: потяни по сукну — кий повернётся вокруг битка (поворот относительный, кий не «прыгает» к пальцу); возьмись за кий позади битка, оттяни его назад и отпусти. Чем дальше оттянул, тем сильнее удар. На широком экране остались и ползунок силы, и кнопка **Ударить**.
5. На широком экране кнопка разворота над столом открывает большой игровой режим (выход — та же кнопка или Escape). На телефоне и в Telegram матч сразу открывается на отдельном экране со столом во весь экран — в горизонтальной ориентации.

### UI-тесты

```sh
npx playwright install chromium
npm run test:e2e
```

Для окружения с уже установленным Chromium можно передать `CHROMIUM_EXECUTABLE_PATH`. Тесты проверяют два клиента, запрет чужого хода, открытие правил во время удара, выход из комнаты, создание приглашения, компактный Mini App на экране 390×844 (поворот в горизонтальный, удар оттягиванием кия, отсутствие кнопки и ползунка), сборку без сервера (ни одной попытки WebSocket, шары останавливаются сами) и мост Telegram SDK с моком. Скриншоты и временные артефакты исключены из Git.

## Что реализовано

- 3D-геометрия стола, материалы сукна, освещение, тени, блики, нумерованные сплошные и полосатые шары. Текстуры генерируются в коде; картинки-заглушки не используются.
- Вращение шаров из рассчитанной угловой скорости. В тренировке — непосредственное отображение координат физики; в онлайне — линейная интерполяция с буфером 70 мс, без экспоненциального «догоняния».
- Прицел с учётом бортов и входов в лузы. Удар — оттягиванием кия: кий едет за пальцем, пройденное расстояние задаёт силу (видна в процентах и м/с), отпускание выпускает кий вперёд за 95 мс. Кнопочный удар (desktop) сохраняет замах с контактом через 210 мс.
- Рендер под телефон: буфер кадра в `devicePixelRatio` до 2×, текстуры шаров 1024×512 с максимальной анизотропией, сферы 48×32, нейтральный тонмаппинг вместо ACES, карта теней 2048, лампа над столом с заметным спадом света к бортам.
- Физика с базовым шагом 120 Гц и адаптивными подшагами на сильных ударах: столкновения с потерей энергии, отскоки от бортов и губок луз, скольжение → качение, шесть луз. Сервер интегрирует прошедшее монотонное время, а не количество вызовов таймера.
- Тренировка с готовой свободной расстановкой.
- Случайный подбор 1 на 1, приватные комнаты, копирование ссылки, вход по коду.
- Авторитетная онлайн-физика: клиент передаёт только угол и силу. Сервер проверяет очередь хода, конечность чисел, движение шаров и окончание партии. Обновления до 30 Гц.
- Группы шаров, переходы хода, ранняя/правильная восьмёрка, возврат битка после лузы.
- Гостевое имя, локальная история законченных партий, переключение звука, правила и адаптивный интерфейс.
- Переподключение WebSocket, уведомления о потере соединения / выходе соперника, heartbeat, лимит размера сообщения, удаление незаполненных комнат через 30 минут.
- Действия клиента ограничены по частоте (100 мс), но выход из очереди или комнаты обрабатывается всегда: отменённый игрок не остаётся в очереди и его комната удаляется сразу. Если сервер не ответил на действие за 5 секунд, кнопка разблокируется с уведомлением.
- Клавиатурный фокус в диалогах, Escape, `prefers-reduced-motion`, сообщение при отсутствии WebGL.

## Модель удара и масштаб

Сила задаёт **начальную скорость одним импульсом** в момент контакта. После контакта никакой постоянной силы от кия нет. Центральный удар сначала вызывает скольжение; трение уменьшает поступательную скорость и раскручивает шар. Для идеального однородного шара переход в чистое качение происходит при `v = 5/7 · v₀`. Далее скорость уменьшается от сопротивления качению. После столкновений возможен обмен поступательной и вращательной энергией — скорость отдельного шара не обязана убывать монотонно, но трение не добавляет суммарную энергию.

Параметры в `shared/table.ts` и `shared/game.ts`:

- Игровая поверхность 8-футового стола: 2,24 × 1,12 м; диаметр шара 57,15 мм.
- `μ скольжения = 0,20`, `μ качения = 0,032`, `g = 9,81 м/с²`. Качение чуть «тяжелее» турнирного сукна (0,010–0,020) намеренно: иначе шары докатываются по полминуты, а это мобильная игра. Порог остановки `0,018 м/с`.
- Коэффициент восстановления шар–шар `0,96`, борт `0,80`.
- Максимальная начальная скорость `5,5 м/с`; шкала нелинейная для точности слабых ударов.
- Геометрия столкновений бортов/губок общая с отображаемой геометрией. На столе реальные вырезы луз и глубокие колодцы, а не чёрные кружки поверх сукна.

Шаги физики привязаны к реальному времени: кадр может «догнать» до 0,25 с, поэтому на слабом устройстве стол замедляется, а не превращается в слоу-мо.

Это **параметризованное приближение**, а не измеренная модель конкретного реального стола. Реальное сукно, борта и шары отличаются. Тесты проверяют начальную скорость, переход скольжения в качение, отсутствие прироста энергии от трения, независимость свободного движения от шага, отсутствие туннелирования и равномерную интерполяцию. Визуальное ощущение и производительность ещё требуют оценки на устройствах.

## Правила и ограничения MVP

Это **упрощённая восьмёрка**, а не турнирная реализация WPA. Первый правильный цветной шар определяет группу. Нужно сначала убрать свою группу, потом восьмёрку. В тренировке до восьмёрки нужно убрать все цветные. Заказ лузы, свободное размещение битка, обязательное касание борта, специальные правила разбоя и управление смещением наклейки кия (винт/оттяжка/накат) пока не реализованы. Удар всегда центральный. Угловая скорость и трение сукна рассчитываются, но это ещё не полная физика spin/english: нет прыжков, массе и тангенциального трения шар–шар.

Комнаты и очередь хранятся **в памяти одного процесса**. Перезапуск сервера / потеря соединения завершает текущую комнату, возобновления матча нет. Завершённые партии сохраняются только в localStorage данного браузера. Закрытая незаконченная партия не попадает в историю. Счётчик клуба показывает подключения, а не уникальные Telegram-аккаунты.

Это не готовый к массовому запуску сервис: нет постоянной БД, рейтинга, аккаунтов, ставок, бот-соперников, таймера хода, распределённого матчмейкинга, защиты от ботов или восстановления партии.

## Telegram

### Интерфейс внутри Telegram

В Telegram и на телефоне (`max-width: 760px`) интерфейс клуба не показывается. Вместо него открывается компактный Mini App (`src/MiniApp.tsx`, `src/mini.css`):

- **Экран меню:** название, счётчик игроков и три кнопки — «Играть онлайн», «Играть с другом», «Тренировка». Внизу — правила, история, имя. Поиск соперника и код комнаты показываются на том же экране.
- **Экран игры:** только стол во весь экран. Поверх него плавают три мелочи: строка «чей ход», кнопки «назад» / «заново» и вертикальная шкала силы, которая появляется, пока кий оттянут. Ни кнопки удара, ни ползунка — удар делается самим кием.
- Экран не прокручивается: высота равна `viewportStableHeight`, отступы берутся из `contentSafeAreaInset` и `env(safe-area-inset-*)`.
- Стол всегда горизонтальный: если экран вертикальный, весь игровой экран поворачивается на 90° (`.is-rotated`), и телефон держат боком, как настоящий кий. Касания пересчитываются под тот же поворот, поэтому кий слушается пальца один в один.
- Кнопка «Назад» Telegram возвращает из игры в меню; выход из онлайн-матча дополнительно спрашивает подтверждение.

Десктопная версия клуба остаётся для широких экранов.

### Мост SDK

Если страница открыта с `tgWebAppData`, приложение загружает официальный Telegram Web App SDK, вызывает `ready()` / `expand()`, задаёт цвета и использует имя для отображения. Учитывает высоту WebView и безопасные отступы; пока открыт стол, отключает вертикальный жест сворачивания на поддерживаемых версиях SDK, а в онлайн-комнате включает подтверждение закрытия. В обычном браузере ничего из Telegram не требуется.

**Статус проверки:** браузерные UI-тесты и отдельный тест с **моком SDK** есть. Это не проверка настоящего Telegram, WKWebView iOS или Android WebView. До утверждения «готово к Telegram» нужно вручную проверить через бота:

- iOS и Android: загрузка WebGL, 30/60 FPS на целевых устройствах, нагрев и расход памяти.
- Прицеливание пальцем, смена ориентации, края экрана и отсутствие конфликтов со свайпом закрытия.
- Сворачивание/возврат, потеря сети, повторное открытие. Сейчас отключение завершает матч, восстановления нет.
- Первый звук после касания, буферизация снимков на мобильной сети и совместный матч двух телефонов.

**Важно:** `initDataUnsafe` используется только как подпись гостя. Серверная аутентификация Telegram пока не реализована, поэтому гостевое имя нельзя считать подтверждённой личностью.

Для публикации:

1. Разверни production-сервер за **HTTPS** с поддержкой WebSocket upgrade и достаточным idle timeout (например 120 секунд).
2. Укажи публичный URL как Mini App / menu button своего бота через BotFather.
3. До публичного рейтинга или аккаунтов добавь серверную проверку подписи и срока действия `initData`, сессии и привязку игрока к проверенному Telegram ID. Токен бота хранится только в серверных секретах, никогда в frontend / репозитории.
4. Добавь БД для пользователей/результатов, reconnect/resume, лимиты запросов по пользователю/IP, ограничения ресурсов и мониторинг.
5. Для нескольких серверов потребуется общий matchmaking и маршрутизация комнат (например Redis), а также нагрузочные тесты.

Приглашение открывается двумя способами: обычной ссылкой `?room=ABCDEF` и Telegram deep link `https://t.me/<бот>/<app>?startapp=ABCDEF`. Второй вариант используется автоматически, если при сборке задан `VITE_BOT_APP_URL`; код комнаты читается из `start_param`, `tgWebAppStartParam` или `?room=`. Сам бот и публичный хостинг в этом репозитории не создаются.

## GitHub Pages + бот

GitHub Pages отдаёт **только статические файлы**: он не может принять WebSocket-соединение и не выполняет серверный код. Поэтому схема такая:

| Что                                   | Где                       | Зачем                              |
| ------------------------------------- | ------------------------- | ---------------------------------- |
| интерфейс, 3D-стол, тренировка        | GitHub Pages              | этот адрес указывается в BotFather |
| очередь, комнаты, авторитетная физика | отдельный хост с `wss://` | игра двух пользователей            |

Пока сервера нет, сборка работает как **тренировочная**: приложение ни разу не пытается открыть WebSocket, в меню видно «Онлайн позже», кнопки онлайна помечены `скоро` и объясняют это при нажатии, а главной кнопкой становится «Тренировка».

Как клиент выбирает адрес (`src/config.ts`, `resolveGameServer`):

1. `?server=wss://...` в адресе страницы — ручная заглушка для проверки будущего сервера; выбор запоминается в localStorage. `?server=off` принудительно оставляет только тренировку, `?server=auto` возвращает поведение по умолчанию.
2. `VITE_GAME_SERVER` из сборки.
3. Локальная разработка (`npm run dev`) — текущий origin через прокси Vite.
4. Иначе один запрос `api/health` к своему origin: отвечает — работаем онлайн, нет — остаёмся в тренировке. На `*.github.io` и подобных статических хостах запрос даже не делается.

### 1. Сборка под Pages

`vite.config.ts` использует относительный `base` (`./`), поэтому сборка одинаково работает и в корне домена, и по адресу `https://<имя>.github.io/<репозиторий>/`. Шрифт и иконка собираются как ассеты с относительными путями, `public/.nojekyll` отключает обработку Jekyll.

Адрес игрового сервера попадает в сборку через переменные окружения (`.env.example`):

```sh
VITE_GAME_SERVER=wss://billiard.example.com npm run build
# необязательно: ссылка на сам Mini App для приглашений
VITE_BOT_APP_URL=https://t.me/your_bot/your_app
```

`VITE_GAME_SERVER` принимает `wss://host`, `https://host` или адрес с путём; `/ws` добавляется автоматически. HTTPS-страница может открывать только `wss://`, обычный `ws://` браузер заблокирует.

### 2. Публикация

В репозитории есть workflow `.github/workflows/deploy-pages.yml`: `npm ci` → `npm test` → `npm run build` → публикация `dist`.

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → **Variables**: `VITE_GAME_SERVER`, при необходимости `VITE_BOT_APP_URL`.
3. Push в `main` — Pages обновится на `https://<имя>.github.io/<репозиторий>/`.

### 3. Сервер онлайна

Подойдёт любой Node-хост с HTTPS и WebSocket (VPS с nginx и сертификатом, Render, Fly.io, Railway и т. п.):

```sh
npm ci && npm run build && PORT=8080 npm start
```

Нужен проксируемый upgrade для `/ws` и idle timeout больше 30 секунд (клиент шлёт heartbeat каждые 30 с). Этот же процесс умеет раздавать `dist`, если захочешь обойтись без Pages.

### 4. Бот

1. BotFather → `/newapp` (или Menu Button) → укажи адрес Pages.
2. Открой Mini App с телефона и проверь: запуск, поворот экрана в горизонтальный, оттягивание кия пальцем, выход кнопкой «Назад».
3. Приглашение друга даёт ссылку `?startapp=КОД`, если задан `VITE_BOT_APP_URL`.

**Проверено автоматически:** сборка с относительным `base`, раздача из подкаталога (`/<репозиторий>/`), подключение к серверу на другом origin, матч двух клиентов, мобильная вёрстка и мост SDK с моком. **Не проверено:** настоящий Telegram на iPhone/Android, реальный домен с сертификатом, поведение сети мобильного оператора.

shared/rendering.ts  линейная интерполяция и движение кия
shared/game.test.ts  тесты физики и правил
server/index.ts      WebSocket, очередь, комнаты, production static
